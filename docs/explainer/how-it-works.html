01Misskey ってなに？

Misskey は、短い文章や画像を投稿して、みんなと見せ合う SNS です。投稿のことを ノート と呼びます。

ふつうの SNS は、1つの会社が1つの大きなサーバーを動かしています。Misskey はちがいます。だれでも自分のサーバーを立てられて、しかも ほかのサーバーの人ともつながれます。この形を「分散型」といいます。

ポイント
  • Misskey は「サーバーのソフト」。1台1台を サーバー（インスタンス）と呼ぶ
  • 投稿は ノート、反応は リアクション（絵文字）
  • ほかのサーバーともつながる 分散型 の SNS

02どこで動くの？

Misskey は、あなたのブラウザとサーバーの2か所で動きます。サーバーの中にはさらに、データをしまう係がいくつかいます。

PostgreSQL

本棚

ノート・ユーザー・フォローなど、消えては困るものを全部しまうデータベース。

Redis

メモ帳

タイムラインの並びや、係どうしの連絡など、すぐ使うものを置く。とても速い。

Drive

ファイル置き場

画像や動画。サーバーのディスクか、S3 のような外部の置き場にしまう。

03係の分担

Misskey のソースコードは、packages/ の中でいくつかの「係」に分かれています。1つのリポジトリにまとめて入れる、モノレポという形です。

packages/backend

サーバー係

API の受付、ノートの保存、ほかのサーバーとのやりとり。NestJS と TypeORM で作られている。

packages/frontend

画面係

ブラウザで見える画面。Vue 3 で作られ、Vite でまとめられる。

packages/misskey-js

通訳係

画面からサーバーの API を呼ぶための道具。型（どんなデータか）は backend から自動で作られる。

packages/sw

見張り係

Service Worker。ブラウザを閉じていてもプッシュ通知を受け取る。

frontend-embed

ほかのサイトにノートを埋めこむための小さな画面。

frontend-shared

画面係どうしで共通に使う部品やテーマ。

i18n

翻訳。locales/ja-JP.yml がもとになる。

04ノートが届くまで

「ノート」ボタンを押してから、フォロワーの画面に表示されるまでを、順番に追いかけてみましょう。

  1. 書く

    投稿フォーム（MkPostForm.vue）で文章を書いて「ノート」を押す。

    packages/frontend

  2. 送る

    misskey-js が POST /api/notes/create にデータを送る。

    packages/misskey-js/src/api.ts

  3. 受付

    ログインしている本人か、送りすぎていないか、書き方が正しいかを確かめる。

    packages/backend/src/server/api/ApiCallService.ts

  4. ノートを作る

    メンションやハッシュタグを取り出し、ID をつけてノートを組み立てる。

    packages/backend/src/core/NoteCreateService.ts

  5. 本棚にしまう

    PostgreSQL に保存。ここで投稿した人に返事が返る。

  6. タイムラインに並べる

    フォロワーそれぞれの「ホームの並び」に、ノートの ID を足す。

  7. 画面にすぐ届ける

    いま画面を開いている人には、WebSocket でその場で届ける。

  8. 他サーバーへ配る

    ほかのサーバーのフォロワーには、配送キューに「届けて」と頼む。

05受付窓口

画面からのお願いは、すべて /api/○○ という窓口に届きます。窓口は 400 個以上 あり、1つの窓口が1つのファイルになっています。

1

だれ？

トークンを見て、だれのお願いかを確かめる（AuthenticateService）。

2

多すぎない？

短い時間に送りすぎていないか数える（RateLimiterService）。

3

書き方OK？

決められた形のデータかを Ajv でチェックする。

窓口ファイルの形
export const meta = {
  requireCredential: true,       // ログインが必要
  limit: { duration: 3600000, max: 300 }, // 1時間に300回まで
};

export const paramDef = {       // 受け取るデータの形
  type: 'object',
  properties: { text: { type: 'string', nullable: true } },
};

// 中身の処理は「係」に頼むだけ
super(meta, paramDef, async (ps, me) => {
  return await this.noteCreateService.create(me, ps);
});

endpoints/notes/create.ts を短くしたものです。meta に決まりごと、paramDef にデータの形を書き、処理は係（サービス）に任せます。paramDef からは misskey-js の型も自動で作られます。

06ノートを作る

ノート作りの中心は NoteCreateService です。保存の前に、いろいろなチェックと準備をします。

保存の前

  • 禁止ワードが入っていないか
  • 返信先・リノート先を見てよいか（ブロックされていないか）
  • 本文から メンション・ハッシュタグ・絵文字 を取り出す（MFM を読む）
  • メンションが多すぎないか（ロールの上限）

保存のあと（後ろで）

  • 投稿数を数える、ハッシュタグを記録する
  • タイムライン・アンテナに入れる
  • メンションされた人に通知する
  • Webhook を呼ぶ、他サーバーへ配る
保存してから、後ろで続きをやる
const note = await this.insertNote(user, data, tags, emojis, mentionedUsers);

// 返事を先に返して、続きはあとで
setImmediate('post created').then(
  () => this.postNoteCreated(note, user, data, ...),
);

return note;

insertNote で保存したら、すぐ return します。タイムラインや配送などの重い仕事は postNoteCreated にまとめて後回しにするので、投稿した人を待たせません。

ID のつけ方ノートの ID には、作った時刻が入っています（aidx などの方式）。だから ID を比べるだけで、どちらが新しいかが分かります。

07タイムライン

ホームを開くたびに「フォローしている全員のノートを集めて並べ直す」と、とても時間がかかります。そこで Misskey は、ノートができたときに、配る先の並びに先に入れておく 方法をとっています。これを ファンアウト と呼びます。

書くとき

配る

FanoutTimelineService が、homeTimeline:ユーザーID のような列の先頭に ID を足す。列が長くなりすぎたら古い方を捨てる。

読むとき

取り出す

notes/timeline は、まず Redis の列から ID を取り出し、中身を PostgreSQL から読む。列に足りないときは PostgreSQL から直接さがす（DB フォールバック）。

08すぐに届く

画面を開いたままにしていると、新しいノートが勝手に流れてきます。これは ストリーミング というしくみです。ブラウザとサーバーの間に WebSocket という「つなぎっぱなしの電話」をつないでおきます。

ポイント
  • ノートができると notesStream という放送が Redis に流れる
  • WebSocket の中は「ホーム」「ローカル」などの チャンネル に分かれていて、それぞれが「この人に見せてよいか」を判断して送る
  • 通知・リアクションなども同じしくみで届く

09ほかのサーバーへ

ほかのサーバーにいるフォロワーにノートを届けるには、そのサーバーの 受け取り口（inbox） に手紙を送ります。手紙の書き方は ActivityPub という決まりにしたがいます。

送る

配送

ノートを Create という「活動」に包み、フォロワーのいるサーバーの inbox に送る。相手が多いと時間がかかるので 配送キュー に入れて少しずつ送る。

受け取る

受信

/inbox に届いた手紙は 受信キュー へ。HTTP 署名で「本当にその人からの手紙か」を確かめてから中身を読む。

相手を探すとき@alice@example.com のような名前から相手を見つけるときは、WebFinger（/.well-known/webfinger）で問い合わせます。

10あとでやる仕事

時間のかかる仕事や、失敗したらやり直したい仕事は、ジョブキュー（BullMQ）に入れておき、別の係が順番にこなします。キューの中身は Redis にしまわれます。

キューやること
deliverほかのサーバーへ ActivityPub の手紙を送る
inboxほかのサーバーから届いた手紙を読む
dbデータの書き出し・読みこみ、アカウント削除など重い作業
relationshipフォロー・ブロックなどの関係の変更
objectStorageファイル置き場のファイルを消す
endedPollNotificationアンケートが終わったら知らせる
postScheduledNote予約しておいたノートを時間どおりに出す
userWebhookDeliver / systemWebhookDeliverWebhook を呼ぶ
systemチャートの集計や掃除など、定期的な作業

キューの名前は packages/backend/src/queue/const.ts、それぞれの係は packages/backend/src/queue/processors/ にあります。

12ことば

ノート
Misskey の投稿。ほかの SNS の「ポスト」にあたる。
サーバー（インスタンス）
Misskey が動いている1台1台。それぞれに管理人がいる。
ActivityPub
分散型 SNS どうしが話すための共通のことば。W3C が決めた。
API
画面がサーバーにお願いをするための窓口。
WebSocket
ブラウザとサーバーをつなぎっぱなしにして、すぐにデータを送れる方法。
ファンアウト
ノートができたときに、配る先の列に先に入れておくやり方。
ジョブキュー
あとでやる仕事を並べておく列。失敗したらやり直せる。
inbox
ActivityPub の手紙を受け取る口。
MFM
Misskey Flavored Markdown。文字を大きくしたり回したりできる飾り。
モノレポ
いくつかのパッケージを1つのリポジトリにまとめて入れる形。
