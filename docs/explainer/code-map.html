01システム構成

frontend

ブラウザで動く

Vue 3 の SPA。API は POST /api/〇〇、リアルタイムの更新は WebSocket で受け取る。

backend

Node.js で動く

NestJS + Fastify。cluster で複数プロセスに分かれ、プロセスどうしは Redis で連絡する。

保存先

3 か所にしまう

PostgreSQL（ずっと残すもの）・Redis（速さが大事なもの）・ファイル置き場（画像など）。

03レイヤー構成

読むときのコツ
  • backend は エンドポイント → Service → EntityService / models の順に呼ぶ。エンドポイントは薄く、中身は Service にある
  • Service どうしはコンストラクタで受け取る（NestJS の DI）。@Inject(DI.xxx) は DB のリポジトリや Redis など
  • frontend は ページ → 部品 → os.ts / misskey-js。API の型は misskey-js の autogen/ にある

04処理の流れ

左のラベルがどこで、カードが何をするか、↓ が次に呼ぶものです。上から順に読みます。

A. ノートを投稿する

  1. frontend
    投稿ボタン

    MkPostForm.vue の post() が misskeyApi('notes/create', …) を呼ぶ

  2. ↓ POST /api/notes/create
    misskey-js
    HTTP で送る

    APIClient.request() が fetch する

  3. ↓ JSON
    server/api
    受付

    ApiCallService が認証・レート制限をして endpoints/notes/create.ts を実行（引数の検査は endpoint-base.ts の Ajv）

  4. ↓ noteCreateService.create(me, ps)
    core
    ノートを作る

    NoteCreateService.create()：禁止ワード・ブロック確認、メンション/タグ/絵文字を抽出

  5. ↓ insertNote()
    保存先
    保存

    PostgreSQL の note テーブルに INSERT。ここで API は返事を返す

  6. ↓ setImmediate → postNoteCreated()
    core
    後ろの仕事

    TL への追加・通知・アンテナ・Webhook・ActivityPub 配送

  7. ↓ fanoutTimelineService.push ・ publishNotesStream ・ deliver キュー
    保存先
    Redis

    フォロワーの homeTimeline:ユーザーID に ID を追加。notesStream を放送

B. ホームタイムラインを見る

  1. frontend
    TL を開く

    MkStreamingNotesTimeline.vue が notes/timeline を読みこむ

  2. ↓ POST /api/notes/timeline
    server/api
    受付

    endpoints/notes/timeline.ts

  3. ↓ fanoutTimelineEndpointService.timeline()
    core
    並びを取り出す

    FanoutTimelineEndpointService が Redis の列から ID を取り、足りなければ DB から探す

  4. ↓ ID の一覧
    保存先
    中身を読む

    PostgreSQL から note を読み、NoteEntityService.pack() で API 用の形にする

  5. ↓ 表示したあと、WebSocket をつなぐ
    frontend
    チャンネルにつなぐ

    stream.useChannel('homeTimeline')

  6. ↓ wss://…/streaming
    misskey-js
    接続を保つ

    streaming.ts（reconnecting-websocket）

  7. ↓ Redis の notesStream を受信
    server/api
    ふるいにかける

    stream/channels/home-timeline.ts の onNote が、見せてよいノートだけ send('note')

C. ほかのサーバーからノートが届く

  1. 相手のサーバー
    手紙を送る

    Create(Note) を HTTP 署名つきで POST

  2. ↓ POST /inbox
    server
    受け取る

    ActivityPubServerService が署名ヘッダーを読み、inbox キューへ

  3. ↓ queueService.inbox()
    queue
    順番に処理

    InboxProcessorService が署名を検証して送り主を確定

  4. ↓ apInboxService.performActivity()
    core/activitypub
    活動を読む

    ApInboxService が Create を見て createNote()

  5. ↓ ApNoteService.createNote()
    core/activitypub
    ノートに直す

    ApNoteService が本文・添付・メンションを Misskey の形に変換

  6. ↓ noteCreateService.create()
    core
    あとは同じ

    ローカルの投稿と同じ NoteCreateService で保存・TL・通知

05データの形

MiNote：DB の note テーブル

項目型役目
idstring作成時刻が入った ID（aidx など）
userId / userHoststring / string | null書いた人。userHost が null ならこのサーバーの人
text / cwstring | null本文 / 注釈（CW）
visibility'public' | 'home' | 'followers' | 'specified'公開範囲
localOnlybooleantrue なら他サーバーへ配らない
replyId / renoteIdstring | null返信先 / リノート元
fileIdsstring[]添付ファイル（drive_file の ID）
mentions / visibleUserIdsstring[]メンションした人 / 指定公開の相手
reactionsRecord<string, number>リアクションごとの数
tags / emojisstring[]ハッシュタグ / 使っているカスタム絵文字
channelIdstring | null投稿したチャンネル
uri / urlstring | null他サーバーのノートなら、そちらでの ID と URL

主な列だけ。返信先のユーザー（replyUserId）などは、検索を速くするためにコピーして持っています。

Packed Note：API が返すノート

項目型役目
id / createdAtstringID と作成日時（ISO 文字列）
userUserLite書いた人の最小限の情報
text / cw / visibility…DB と同じ
filesDriveFile[]fileIds を中身に展開したもの
reply / renoteNote返信先・リノート元も pack 済み
reactions / reactionCountRecord / numberリアクションの集計
myReactionstring | null見ている人が付けたリアクション

NoteEntityService.pack() が DB の行を、見ている人に合わせてこの形にします。misskey-js では Misskey.entities.Note。

エンドポイントの meta と paramDef

項目型役目
requireCredentialbooleanログインが必要か
requireModerator / requireAdminbooleanモデレーター・管理者だけか
kindstringトークンの権限（例：write:notes）
limit{ duration, max }レート制限（例：notes/create は 1 時間 300 回）
errorsRecord返しうるエラーと ID
resJSON Schema返事の形。misskey-js の型になる
paramDefJSON Schema受け取るデータの形。Ajv で検査し、misskey-js の型にもなる

ジョブのデータ

項目型役目
DeliverJobData.userThinUser送り主（このサーバーのユーザー）
DeliverJobData.contentstring送る Activity（JSON 文字列）
DeliverJobData.tostring相手の inbox の URL
DeliverJobData.isSharedInboxbooleanサーバー共通の inbox か
InboxJobData.activityIActivity届いた Activity
InboxJobData.signatureIParsedSignatureHTTP 署名（検証に使う）

08横断的な仕組み

しくみ場所ひとこと
DI（係のつなぎこみ）
NestJS のモジュールで係を登録し、コンストラクタで受け取る
設定
.config/default.yml を読む。サーバー設定（Meta）は DB 側
DB の変更
エンティティを変えたら、新しいタイムスタンプで migration を追加
API の型
backend の paramDef / res から misskey-js の型を自動生成
翻訳
ja-JP.yml だけを直す。ほかの言語は Crowdin が配る
画面の URL
URL とページ（pages/*.vue）の対応表
ダイアログ
os.alert / os.confirm などはここから
キーボードショートカット
v-hotkey で登録
テーマ
色は CSS 変数（--MI_THEME-*）
起動
cluster で master と worker に分かれて動く

よくある変更の入口

やりたいこと触る場所
API を足す・変える にファイルを置き、 に登録。最後に pnpm build-misskey-js-with-types
DB の列を足す を直し、 に新しい migration（up / down 両方）
画面の部品を直す の Mk*.vue。<script setup lang="ts"> で書く
文言を足す にキーを足し、i18n.ts.キー で使う
ストリーミングのチャンネルを足す と
ジョブを足す・・
